# 규칙은 YAML로만 정의하고 Rust는 범용 실행 엔진을 담당한다

2026-09-08: [Rust 전용 규칙 결정](0002-rust-only-rules.md)으로 대체되었습니다. 아래는 당시 결정의 기록입니다.

새 규칙마다 `hasLoopAccumulator` 같은 전용 조건을 Rust에 추가하면 YAML은 실제 규칙을 표현하지 못하는 설정에 머문다. 규칙 작성 방식은 YAML로 통일하고, Rust는 YAML에 정의한 규칙을 해석·실행하는 범용 기능만 제공한다. YAML로 표현하기 어려운 규칙을 별도의 Rust `Rule` 구현으로 우회하는 혼합 구조는 채택하지 않는다.

규칙의 표현력이 부족하면 AST 노드 종류·속성 검사, 자식·후손·조상 탐색, 노드 캡처와 참조, 동일 바인딩 비교, 탐색 경계와 보고 단위 같은 재사용 가능한 기능을 엔진에 추가한다. 특정 코딩 정책이나 패턴의 판단 자체를 Rust에 하드코딩하거나, 이름만 범용적인 전용 조건으로 감싸서는 안 된다. 필요한 규칙을 YAML로 구현할 수 없는 구조를 유지한다면 YAML을 완전히 제거하는 방향을 다시 결정해야 하며, 일부 규칙만 Rust로 작성하는 예외는 허용하지 않는다.

예를 들어 지역 빈 배열 선언과 반복문 내부의 동일 배열에 대한 `push`를 연결하는 조건은 전부 YAML로 조합한다. 중첩 함수 제외와 함수당 한 번 보고하는 정책도 YAML에서 표현한다. 순수성·동작 보존 여부를 확인하는 AI 판단 기준 역시 YAML에 두고, Rust는 후보 추출과 모델 요청 실행을 담당한다.

당시 구현은 YAML v2 문법을 따랐다. 기존 규칙 전용 조건과 작업 중이던 `hasLoopAccumulator`는 제거하고, 기본 규칙과 예제도 범용 YAML 쿼리로 정의했다. 해당 문법과 구현은 ADR-0002에 따라 제거되었으며 이전 커밋에서 확인할 수 있다.
